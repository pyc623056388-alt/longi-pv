PROJECT BRIEF · FOR MANAGEMENT

AU Distribution Task Management

隆易 KK / 钉钉 AI 表格 · 团队任务管理项目说明

受众：管理者及核心对齐同事（如 Jack）
平台：隆易 KK · AI 表格（Task Collection Form + 数据表 + 多视图）
版本：v1.0 · 2026-07

一句话定位：统一需求收集、按角色线分工跟踪、支撑周会治理——把 Task Management Table 当作一个可运营的 Project，而不是第二张周会 Excel。

A. 项目目标与范围

要解决什么

  • 统一入口：通过 Task Collection Form 收集任务需求，避免散落在聊天与周报里。
  • 主责清晰：Task Type = 角色线；Workstream = 该类角色下的一般分工；负责人唯一。
  • 状态可见：进行中 / 阻塞 / 逾期可筛选，周会可投屏跟进。
  • 支持可升级：需要跨人协助时结构化标记（支持人 / 说明），可触发提醒。

明确不解决什么（边界）

  • 合同明细台账、授信全量档案
  • 库存 MW / POD 明细运营报表
  • 全年活动总日历与营销基金完整台账
上述专项内容继续用独立表格或文档维护，在任务记录中用链接 / 附件挂接即可，避免 Task 表膨胀成「万能表」。

B. 整体流程

Task Collection Form（提交需求） │ ▼ Tasks 数据表（一条记录 = 一项任务） │ ├──────────────► 自动化：DDL 提醒 / 需支持通知 / 周更提醒 │ ▼ 多视图：My Tasks · Weekly Meeting · Kanban · Overdue · Archive │ ▼ 周会投屏 Weekly Meeting（只盯 P0/P1、需支持、将逾期）

角色分工：任何人可通过表单提单 → 指定负责人执行与更新进展 → 管理者用视图做周会治理与例外管理。

E. 与 AU Action Tracking 的对应与迁移

现有 AU Distribution Team Action Tracking 是「周会汇报稿 + 任务跟踪」混排的层级 Excel。迁入 AI 表格时不要 1:1 粘贴。

原表问题AI 表格做法
类别 / Key Tasks 靠空单元格「继承」每行补全 Task Type + Workstream
任务、周会提问、运营汇总混在一行一行一事；汇总类可少迁或挂链接
Status 写法不统一（Done / Under way / Ongoing…）统一为固定单选（见 H）
【Latest Status】与【Planned Action】挤在一格拆成 Latest Progress + Next Action
Comments 里自由 @ 人支持人 + Need Support + Support Note

迁移原则

  1. 优先迁移 仍进行中 的项；已 Done 进 Archive 或暂不迁。
  2. 把原「类别」映射到 Task Type；「Key Tasks」映射到最接近的 Workstream。
  3. Product → 一律改为 Product & Solution。
  4. 清洗完成后再开全员填写；先小范围试跑 10–15 条。

F. 推荐视图与自动化

视图

视图名用途建议筛选 / 分组
My Tasks个人待办负责人 = 我；Status ≠ Done
Weekly Meeting周会投屏P0/P1，或 Need Support，或近 7 天有更新 / 将逾期
By Type按角色线审视按 Task Type 分组
Kanban状态流转按 Status 看板
Overdue例外管理截止日期 < 今天 且未 Done
Archive历史Status = Done（默认不进周会）

自动化（优先 3 条）

  1. DDL 前提醒：截止日期前 2–3 天通知负责人。
  2. 需支持通知：勾选 Need Support 或填写支持人时，通知对应人员。
  3. 周更提醒：固定工作日提醒更新 Latest Progress + Next Action。

G. 填写规范与周会用法

Do

  • 一行一事；Owner 唯一；选对 Task Type + Workstream。
  • 每周更新 Latest Progress，并写清 Next Action（可执行、有对象）。
  • 需要别人做事：勾选 Need Support，指定支持人，写清需要什么。
  • 周会只投屏 Weekly Meeting，按例外与阻塞推进。

Don’t

  • 不要用空行「继承」上一行的类别（Excel 习惯）。
  • 不要把整段周报、库存 MW、活动长名单塞进一条任务。
  • 不要自创 Status 文案；不要多人并列「共同 Owner」。
  • 不要双写：AI 表格已跟进的事项，不必再在旧 Action Tracking 重复维护。
周会建议节奏：先看 Overdue → 再看 Need Support → 再看各角色线 P0/P1 → 当场改 Status / 指定支持 / 调整 DDL。
